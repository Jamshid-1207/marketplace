# Руководство пользователя

**Статус:** Актуально · **Дата:** 2026-10-29 · **Ревизия:** 1

Как запустить Marketplace на своём компьютере и пользоваться им: покупателем на витрине, продавцом в кабинете и админом платформы. Как система устроена внутри — в [SD-00](system-design/00-overview.md) и [ADR](adr/); что и зачем делается — в [ТЗ](TZ.md).

## 1. Что это

Marketplace — площадка, где продают несколько магазинов, а покупатель оформляет один заказ сразу у нескольких из них. Цены — в сумах. Три приложения:

| Приложение | Адрес                 | Кто пользуется                                              |
| ---------- | --------------------- | ----------------------------------------------------------- |
| Витрина    | http://localhost:3001 | Покупатель: каталог, корзина, оформление и оплата, мои заказы |
| Кабинет    | http://localhost:3002 | Продавец и его сотрудники: товары, склады, заказы, финансы. Админ платформы: магазины, модерация, категории, комиссия |
| fake-psp   | http://localhost:4000 | Тестовый платёжный провайдер: страница оплаты с кнопками «Оплатить» и «Отклонить» |

Деньги не настоящие: оплата, возвраты и выплаты идут через fake-psp. Письма покупателям и продавцам не уходят наружу — они собираются в Mailpit.

## 2. Запуск и остановка

Нужны Docker Desktop (на Windows — с WSL 2, ему достаточно 8 ГБ памяти), Node.js ≥ 24.11.1 и pnpm 12. Команды — в Git Bash, в папке проекта.

Первый запуск — 10–20 минут, пока собираются образы:

```bash
pnpm install
cp .env.example .env
pnpm infra:up
docker compose --profile full up -d --build
```

Стенд готов, когда все контейнеры `healthy`:

```bash
docker compose --profile full ps
```

Дальше — быстро: `docker compose --profile full up -d` запускает, `docker compose --profile full down` останавливает. С ключом `-v` (`down -v`) удаляются и данные: при следующем запуске база снова будет только с демо-данными.

Демо-данные создаются сами: магазины A и B с 18 товарами в категориях «Электроника», «Телефоны», «Дом», «Кухня», склады и остатки, тестовые пользователи.

## 3. Тестовые пользователи

Пароль у всех — значение `DEV_USER_PASSWORD` из `.env` (в `.env.example` — `dev-password-1`). Вход один на витрину и кабинет: те же email и пароль.

| Email                        | Кто                                                    |
| ---------------------------- | ------------------------------------------------------ |
| `buyer-1@marketplace.test`   | Покупатель                                             |
| `buyer-2@marketplace.test`   | Ещё один покупатель                                    |
| `seller-a@marketplace.test`  | Владелец «Магазина A»: видит все разделы кабинета      |
| `seller-b@marketplace.test`  | Владелец «Магазина B»                                  |
| `manager-a@marketplace.test` | Сотрудник «Магазина A» с одним правом — заказы         |
| `admin@marketplace.test`     | Админ платформы: раздел «Админка»                      |

Можно и зарегистрироваться на витрине: email и пароль не короче 8 символов.

## 4. Покупатель: витрина

### Каталог

- Слева — **категории** и фильтры: **«Цена от, сум» / «до»**, **«Только в наличии»**, кнопки **«Показать»** и **«Сбросить»**. Сверху — поиск **«Найти товар»**.
- Карточка товара в каталоге показывает цену «от» (у товара бывает несколько вариантов) и магазин; закончившийся товар помечен **«Нет в наличии»**.
- На странице товара — продавец, **вариант** (цвет, объём и т. п.), **количество** и кнопка **«В корзину»**.

### Корзина

- Корзину можно собирать **без входа**. После входа или регистрации она объединяется с корзиной аккаунта.
- В одной корзине — товары разных магазинов, они сгруппированы по магазинам. До 50 позиций.
- Позиция, которая закончилась или снята с продажи, помечена **«Недоступен — в заказ не войдёт»** — её можно удалить.
- **«Оформить заказ»** — для гостя сначала **«Войдите, чтобы оформить заказ»**.

### Оформление и оплата

1. На странице **«Оформление заказа»** — данные доставки: **«Получатель»**, **«Телефон»** в формате `+998XXXXXXXXX`, **«Адрес»**, и состав заказа.
2. **«Оплатить … сум»** — заказ создан, система проверяет наличие и резервирует товар на складах продавцов.
3. Открывается страница fake-psp: **«Оплатить»** — оплата прошла, **«Отклонить»** — как будто банк отказал.
4. После оплаты — возврат на страницу заказа: через пару секунд статус **«Заказ оформлен»**.

Оплатить нужно **за 15 минут**, иначе заказ отменится и резерв освободится. Если банк отказал — **«Вернуться в магазин»**, на странице заказа **«Перейти к оплате»** и вторая попытка.

Статусы заказа на витрине:

| Статус                | Что происходит                                                    |
| --------------------- | ----------------------------------------------------------------- |
| Проверяем наличие     | Резерв товара на складах продавцов                                |
| Ожидает оплаты        | Товар зарезервирован, ждём оплату                                 |
| Подтверждаем оплату   | Оплата авторизована: списываем остаток со склада и деньги с карты |
| Заказ оформлен        | Всё прошло, продавцы получили свои части заказа                   |
| Заказ отменён         | С причиной: товара не хватило, оплата не прошла, время истекло…   |

### Мои заказы

- **«Мои заказы»** — список с суммой и датой; в заказе — **части по магазинам** (под-заказы) со своими статусами: «Собирается», «Отправлен», «Доставлен», «Отменён».
- Часть заказа можно **«Отменить»**, пока продавец её не отправил: деньги за неё вернутся на карту («Деньги возвращаются» → «Деньги возвращены»), остальные части не меняются.
- Письма о заказе — подтверждение, отправка, доставка, отмена, возврат — приходят в Mailpit: http://localhost:8025.

## 5. Продавец: кабинет

Вход — http://localhost:3002, тем же email и паролем, что на витрине. **Меню зависит от роли:** владелец видит все разделы, сотрудник — только разделы своих прав, админ — «Админку». У пользователя без магазина в меню только **«Открыть магазин»**.

### Сводка

Числа на сегодня: **под-заказов к отгрузке**, **доступно к выплате**, **в ожидании**, **SKU с низким остатком**.

### Товары

1. **«Новый товар»** → название → **«Создать черновик»**.
2. В черновике — **«Описание»**: название, **категория**, описание, **изображения** (ссылки, по одной на строку, до 10) → **«Сохранить»**.
3. **«Варианты (SKU)»**: код, атрибуты (по одному на строку: «Цвет: чёрный»), **«Цена, сум»**, **«Продаётся»** → **«Добавить»**. Без вариантов товар не отправить на модерацию.
4. **«Отправить на модерацию»** — статус «На модерации». Когда админ одобрит — «Опубликован», товар на витрине. Если отклонит — «Отклонён» с причиной: исправьте и отправьте снова.

У опубликованного товара **цена и «Продаётся» меняются сразу**, а изменённое описание, код или атрибуты снова идут на модерацию — до решения товар снят с витрины. **«В архив»** — убрать товар совсем.

### Склады и остатки

- **Склады:** название, **приоритет** и **«Работает»**. Резерв берётся с первого по приоритету склада, где хватает товара (меньше число — раньше); выключенный склад не резервирует.
- **Остатки** по каждому SKU и складу: **«На складе»**, **«В резерве»**, **«Свободно»**.
- **Приход и списание:** **«Количество»** (плюс — приход, минус — списание), **«Причина»** → **«Провести»**. Списать больше свободного нельзя — кабинет объяснит почему.
- **«Порог»:** когда свободного станет не больше порога, SKU отметится **«Низкий остаток»**, а продавцу придёт письмо «Товар заканчивается».

### Заказы

- Фильтр по статусу: «Ожидает оплаты», «К отгрузке», «Отгружен», «Доставлен», «Отменён».
- В заказе — товары, суммы и **адрес доставки**; контактов покупателя нет — их видит только платформа.
- Действия: **«Отгрузить»** (заказ «К отгрузке»), затем **«Доставлен»**; **«Отменить»** — до отгрузки, покупателю вернутся деньги.

### Финансы

- **«В ожидании»** — деньги за оплаченные под-заказы. Через срок удержания после доставки (по умолчанию **7 дней**) они переходят в **«Доступно к выплате»**.
- **«Запросить выплату»** — от минимальной суммы (по умолчанию **100 000 сум**); статусы выплаты: «Запрошена» → «Отправляется» → «Отправлена» → «Выплачена».
- **«Операции»** — каждое движение денег: оплата заказа, конец удержания, возврат, выплата. **«Сводка продаж»** — расчёты платежей рядом с реестром продаж склада: числа должны совпадать.
- Комиссию платформы удерживает сама платформа: продавцу начисляется сумма за вычетом ставки категории.

Чтобы на стенде не ждать неделю, задайте короткое удержание в `.env` и перезапустите payment — деньги станут доступны примерно через минуту после доставки:

```bash
echo 'SELLER_HOLD_MS=60000' >> .env
docker compose --profile full up -d payment
```

### Покупатели

Покупатели магазина по **сегментам** — «Новый», «Постоянный», «VIP», «Спящий» — и профиль: заказы, сумма покупок, средний чек, возвраты, события. Без контактов покупателя.

### Сотрудники (только владелец)

- **«Добавить сотрудника»** по email: пользователь уже зарегистрирован на маркетплейсе и не состоит в другом магазине.
- **«Права»:** товары, склады, заказы, покупатели, финансы — галочками → **«Сохранить права»**. Меню сотрудника меняется сразу.
- **«Убрать из магазина»** — доступ пропадает.

Проверьте на `manager-a@marketplace.test`: у него в меню только «Заказы».

### Свой магазин

Новый пользователь: войти в кабинет → **«Открыть магазин»** → название → **«Открыть магазин»**. Кабинет доступен сразу, магазин — **«На модерации»**: товары можно готовить и отправлять на модерацию, но на витрину они попадут, когда админ одобрит и магазин, и товары. Письма «Магазин на модерации» и «Магазин одобрен» — в Mailpit.

## 6. Админ платформы

Вход — `admin@marketplace.test` в кабинете, раздел **«Админка»**.

| Раздел               | Что делать                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------ |
| Магазины             | Фильтр по статусу; **«Одобрить»**, **«Отклонить»**, **«Заблокировать»** — с причиной. У заблокированного магазина закрываются разделы кабинета |
| Модерация товаров    | Очередь: текст, варианты, цены, изображения; **«Одобрить»** или **«Отклонить»** с причиной отказа |
| Категории            | Дерево категорий: **«Новая категория»** в корне или внутри выбранной, **«Переименовать»**   |
| Комиссия и отчёты    | **Ставки комиссии** в процентах — по категориям и по умолчанию (вложенная категория без своей ставки берёт ставку родителя); **отчёт по комиссии** за период; **«Проверить журнал»** — сверка всех денежных проводок |
| Покупатели           | Поиск покупателя по email и профиль 360°: заказы, сумма покупок, сегмент, события           |

## 7. Сквозной сценарий за 15 минут

1. **Витрина, гость:** положите в корзину товар «Магазина A» и товар «Магазина B».
2. **«Оформить заказ»** → войдите как `buyer-1@marketplace.test` — корзина сохранилась.
3. Заполните доставку → **«Оплатить»** → на fake-psp **«Оплатить»** → **«Заказ оформлен»**, в заказе две части — по одной на магазин.
4. **Mailpit:** письмо «Заказ … подтверждён» покупателю и «Новый заказ …» каждому продавцу.
5. **Кабинет, `seller-a`:** «Заказы» → заказ «К отгрузке» → **«Отгрузить»** → **«Доставлен»**. На витрине у покупателя эта часть — «Доставлен».
6. **Витрина, `buyer-1`:** вторую часть (магазин B) — **«Отменить»** → «Деньги возвращены»; часть магазина A не изменилась.
7. **Кабинет, `seller-a`:** «Финансы» — деньги в ожидании и операция «Оплата заказа»; «Склады и остатки» — остаток уменьшился.
8. **Кабинет, `admin`:** «Комиссия и отчёты» → **«Проверить журнал»** — «Инварианты журнала выполнены».
9. **Новый магазин:** зарегистрируйтесь на витрине новым email → кабинет → «Открыть магазин» → товар с вариантом → на модерацию; под `admin` одобрите магазин и товар — товар на витрине.

## 9. Если что-то не так

- **«Сервис временно недоступен»** на витрине или в кабинете — какой-то сервис ещё запускается или упал: `docker compose --profile full ps`, логи — `docker compose --profile full logs -f <сервис>` (например, `order`).
- **Docker Desktop на Windows: «Insufficient system resources exist to complete the requested service»** — compose открыл слишком много параллельных запросов. Перед командой: `export COMPOSE_PARALLEL_LIMIT=4`, затем повторите.
- **Заказ долго «Проверяем наличие» или «Подтверждаем оплату»** — на этих шагах работают события между сервисами: проверьте, что `erp`, `payment` и `order` в статусе `healthy`.
- **Порт занят** — стенд занимает 1025, 3000–3002, 3005, 4000, 4318, 5432, 8025, 8080, 9090, 9092 и 16686: закройте программу, которая держит порт, и запустите стенд снова.
- **Начать с чистого листа:** `docker compose --profile full down -v`, затем `pnpm infra:up` и `docker compose --profile full up -d`.
