# ADR-0002: Kafka как брокер событий

**Статус:** Принято · **Дата:** 2026-10-22

## Контекст
Нужна асинхронная шина между сервисами, с гарантией порядка внутри агрегата и возможностью переиграть события (replay). Например, пересчитать сегменты CRM по истории.

## Варианты
| | RabbitMQ | **Kafka** |
|---|---|---|
| Модель | Очереди, push | Лог, pull, хранение |
| Replay | Нет | Да (offset) |
| Порядок | В очереди | В партиции (по ключу) |
| Локально | Легко | Тяжелее (KRaft убирает Zookeeper) |
| Рынок/собесы | Часто | Очень часто |

## Решение
Kafka в режиме KRaft, клиент `kafkajs` (через NestJS microservices transport или собственный адаптер в `libs/kafka`). Один топик на bounded context, ключ партиции = `aggregateId`, DLQ на каждый топик.

## Последствия
- Consumer groups на каждый сервис, поэтому один и тот же `payment.succeeded` независимо читают ERP и CRM.
- Доставка at-least-once, значит consumers обязательно идемпотентны.
- Kafka UI в docker-compose для отладки.
