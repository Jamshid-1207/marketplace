# ADR-0004: Database per service

**Статус:** Принято · **Дата:** 2026-10-22

## Контекст
Если у сервисов общая БД, между ними появляется скрытая связность, и смысл микросервисов теряется.

## Решение
У каждого сервиса своя логическая БД PostgreSQL и своя схема Prisma. Локально всё живёт на одной инстанции Postgres (init-скрипт создаёт `auth_db`, `catalog_db`, `order_db`, `payment_db`, `erp_db`, `crm_db`, `notif_db`).
Чужие данные сервис получает только через события. Если нужно, держит локальную read-model: например, CRM хранит копию `customer_orders` из событий order и payment.

## Последствия
- Кросс-сервисных JOIN нет, отчёты строим на read-models.
- Консистентность между сервисами eventual, обеспечивается через Saga и Outbox.
- Прод-окружение может разнести БД по разным инстанциям без изменений в коде.
