# ADR-0001: Микросервисная архитектура

**Статус:** Принято · **Дата:** 2026-10-22

## Контекст
Pet-проект для практики System Design. Домены ERP и CRM естественно разделяются (bounded contexts), и между ними много асинхронных взаимодействий.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Модульный монолит | Просто, одна транзакция, быстрый старт | Меньше практики распределённых паттернов |
| **Микросервисы** | Изоляция доменов, независимые БД, практика Saga/Outbox/Kafka | Eventual consistency, сложнее отладка и локальный запуск |
| Гибрид | Компромисс | Размытые границы |

## Решение
Микросервисы: 8 backend-сервисов (gateway, auth, catalog, order, payment, erp, crm, notification).

## Последствия
- Нужны Outbox, идемпотентность, Saga, correlation-id. Всё это закладываем в общие libs на этапе 1.
- Чтобы локальный запуск был простым: docker compose, одна инстанция Postgres с отдельными БД.
